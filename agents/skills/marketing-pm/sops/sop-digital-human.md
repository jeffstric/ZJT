# 数字人视频流程

## 适用场景

用户需要生成数字人视频，例如：
- "让这张图里的人说这段话"
- "用这张人物图片生成口播视频"
- "生成数字人口播"
- "用图片和文案做一个会说话的人物视频"

## 不适用场景

以下需求不是数字人视频，不能走本流程：
- 视频克隆、视频复刻、参考视频复刻
- 替换已有视频里的模特或人物
- 基于参考视频保持动作/镜头/场景并换人物

这些需求必须加载视频克隆 SOP，并调用 `marketing-video` 专家处理。

## 声音方案判定矩阵（数字人口播 · TTS 驱动版）

用户素材组合不同，流程与确认要求不同。**核心红线：任何 AI 生成的要素（文案/角色图/驱动音频）未经用户确认，不得提交数字人视频生成（会消耗视频算力）**。唯一例外：图片与驱动音频都由用户自己提供时可直接生成。

| 用户输入组合 | 流程 | 是否需要确认 |
|---|---|---|
| 图片 + 驱动音频（用户上传） | 直接生成 | ❌ 无需确认 |
| 图片 + 参考音色（用户指定音色库音色或声音要求） | TTS 合成驱动音频 → 展示试听 | ✅ 确认音频后生成 |
| 图片 only | VL 看图选音色 → TTS 合成 | ✅ 确认音色与试听 |
| 文案 + 图片 | 看图选音色 → TTS | ✅ 确认试听 |
| 仅对话意图/文案（无图） | 生成/润色文案 → 文生图生成角色图 → 选音色 → TTS | ✅ 全套确认（文案+图+试听） |
| 音频 only（无图） | 引导补角色图（上传或文生图）→ 图需确认 | ✅ |
| 音色 only | 生成文案 → TTS → 引导补图 | ✅ |

确认交互要求：
- 确认消息必须包含：口播文案全文、角色图预览、音色名与选择理由、**音频试听链接**、两段算力消耗（TTS 已耗 + 视频将耗）
- 用户可单项修改（"换个男声""图片重画""文案改短"）→ 只重做对应项并重新确认
- 用户明确回复"确认/可以/生成"后才可调用 confirm_digital_human

## 流程步骤

### 步骤1：收集数字人素材

如果用户已经提供对应信息则跳过；缺失时使用 `ask_user` 收集：

1. **人物图片（必填）**：用于生成数字人的静态人物图
2. **口播文本（必填）**：数字人需要说的话
3. **参考音频（可选）**：如果用户上传了音频，必须透传真实音频 URL；否则由专家调用 `generate_reference_audio` 按文本生成通用参考音频
4. **画面比例/时长**：从用户视频偏好中读取，用户未设置时由专家按工具默认值处理

### 步骤2：委托给数字人专家

收集完需求后，必须调用 `call_agent` 将任务委托给数字人专家 `digital-human-creator`。

```
call_agent(
    AgentName="digital-human-creator",
    task_description="请为用户生成数字人视频，需求如下：
    - 人物图片：[图片URL]
    - 口播文本：[用户提供的文案]
    - 参考音频：[音频URL；如无音频，请调用 generate_reference_audio 生成]
    - 比例/时长：[从用户视频偏好中读取]

    这是数字人口播任务：让图片中的人物开口说话并生成口型同步视频。禁止按视频克隆处理。",
    user_input="[用户的原始描述]"
)
```

委托要求：
- 如果用户已经上传音频，PM 必须在任务描述中明确写出真实音频 URL，而不是只写"用户已提供参考音频"
- 如果用户没有上传音频，专家必须调用 `generate_reference_audio` 生成通用参考音频

### 声音方案：TTS 驱动音频（推荐路径）

用户没有上传驱动音频时，优先走 TTS 驱动路径（音色更可控、有试听确认）：
1. 专家按"声音方案判定矩阵"准备素材：口播文案（用户未给时先撰写）+ 角色图
2. 专家调用 `prepare_digital_human_draft`（参数：image_url / script_text / 可选 voice_id 与 voice_requirement）：
   - 用户指定了音色库音色 ID → 传 voice_id
   - 用户描述了声音要求（如"成熟男声"）→ 传 voice_requirement，视觉模型看图挑选
   - 都没有 → 视觉模型自动挑选并给出理由
3. 工具返回草案（draft_id / 试听链接 / 算力消耗）→ **必须向用户展示并等待确认**
4. 用户确认后调用 `confirm_digital_human(draft_id)` 提交 MiniMax H3 生成视频
5. 草案 30 分钟有效；过期或用户要改时重新 prepare（只重做修改项：改文案/换音色只需重跑 prepare）
- **人物图片必须写真实图片 URL**（http(s) 或对话中出现过的 `/upload/...` 路径）：用户说"用之前生成的图"时，不得只写"project_id:xxx 的图"这类引用——直接写"使用 project_id xxx 生成的图，请先调用 check_image_status(project_id) 获取真实图片 URL"，由专家查询后再提交；禁止在任务描述中编造图片路径
- 专家必须实际调用 `generate_digital_human` 提交任务；严禁只返回"参数已准备完成，可以提交"
- 专家返回结果必须包含非空 `project_ids`，否则视为未提交成功

### 步骤3：确认专家返回并结束

专家 `digital-human-creator` 返回工作总结后，分两种情况：

**已提交（总结含非空 `project_ids`）**：
- 告知用户任务已提交即可，前端会自动轮询视频生成进度并展示结果，不要重复报告进度
- 使用的图片、文本、音频信息可简要转述

**未提交（总结无 `project_ids`，如音频仍在生成、流程被中断）**：
- 必须如实告知用户当前进展和卡点（如"参考音频还在生成中，数字人视频尚未提交"）
- 给出后续选项，如让用户重新发起生成
- 严禁说"系统会自动处理后续流程""完成后会自动展示"——没有任何自动续接机制，不处理用户会一直等不到结果

## 注意事项

1. **必须调用数字人专家**：数字人视频只委托给 `digital-human-creator`
2. **不要调用营销视频专家**：`marketing-video` 用于普通视频生成和视频克隆，不负责数字人口播
3. **不要混淆视频克隆**：如果用户提供参考视频并要求复刻/替换模特，应切换到视频克隆 SOP
4. **不要重复报告进度**：专家返回工作总结后，不要再说"视频正在生成中，请稍等"
