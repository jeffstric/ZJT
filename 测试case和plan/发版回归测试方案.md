## 三、测试策略

四层递进，前一层不通过则不进入下一层：

```
第 1 层：CI 自动化        →  pytest 全量 + 红线 lint（R4/R6/R7/R8）必须绿
第 2 层：冒烟（5~10 分钟） →  用例文档「模块 0」，P0 阻断性问题优先拦截
第 3 层：功能回归         →  定向用例（本版改动）先行，存量回归用例跟进
第 4 层：验收走查         →  管理员账号全后台走查 + 生产配置核对
```

**定向优先原则**：本版改动涉及的模块（模型选择器、算力结算、退费、故事板拆分/补图、营销智能体设置面板）优先执行；存量模块按 P0 → P1 → P2 顺序执行，时间不足时 P2 可裁剪。

**自动化补充**：

| 项目 | 内容 | 通过标准 |
|------|------|----------|
| pytest 全量 | `tests/` 全量单测（含 driver_integration、regressions） | 全绿，无 skip 异常 |
| 前端单测 | vitest（web/js 下 *.test.js，如 storyboard_batch_first_frame_protect） | 全绿 |
| CI 红线 | scripts/lint_blocking_calls.py（R4/R6/R7/R8） | 无违例 |
| e2e | auto_test/e2e（如环境允许） | 主链路通过 |

## 五、准入与准出标准

### 5.1 准入标准（开始测试前必须满足）

- [ ] v2.6.3 已部署至测试环境，版本号核对无误
- [ ] CI 流水线全绿（pytest、vitest、红线 lint）
- [ ] alembic upgrade head 在测试库执行成功
- [ ] 测试账号与算力余额就绪，历史任务数据已准备
- [ ] 上版遗留问题已评估并标注处理方式

### 5.2 准出标准（允许发版的条件）

- [ ] 冒烟用例 100% 通过
- [ ] 所有 P0 用例通过，无 open 的阻断/严重缺陷
- [ ] P1 缺陷 ≤ 3 个且均有规避方案与修复排期
- [ ] 本版 11 项改动对应定向用例全部执行，预期结果与实际一致
- [ ] 退费/算力金额一致性专项（模块 6）零差异
- [ ] 三平台至少各完成 1 次启动 + 核心页面走查
- [ ] 《发版回归测试用例.md》执行记录填写完整，缺陷单已归档

### 5.3 缺陷等级定义

| 等级 | 定义 | 处理方式 |
|------|------|----------|
| 阻断 | 核心链路不可用（登录、生成、结算、退费） | 立即停止发版，修复后重跑冒烟 |
| 严重 | 功能错误但有临时规避；金额/数据不一致 | 发版前修复或明确回滚方案 |
| 一般 | 体验问题、非主路径边界异常 | 可带缺陷发版，记录排期 |
| 轻微 | 文案、样式瑕疵 | 记录即可 |
