# 供应商切换差价结算方案（"贵扣便宜用"修复）

> 提交：develop_669｜日期：2026-08-20｜前置：《退费扣返一致性修复.md》（失败退费已按流水原额退还）

## 1. 背景与目标

任务创建时按供应商A价格扣费（如 site1 10秒=55分），失败后切换到供应商B重试并成功
（如慧梦 10秒=14分），旧机制不结算差价：用户多付41分（实例：任务 28928）；
反向（便宜扣、贵渠道完成）则平台少收。

**目标**：任务成功时按**实际完成供应商**的价格双向结算差价。

## 2. 结算规则

| 情形 | 含义 | 动作 | 流水号 |
|---|---|---|---|
| 实扣 > 实际价 | 多扣（贵扣便宜用） | 退差 increase | `diff-refund-{原扣费流水号}` |
| 实扣 < 实际价 | 少扣（便宜扣贵用） | 补收 deduct | `diff-charge-{原扣费流水号}` |
| 实扣 = 实际价 | 无差价 | 跳过 | — |

- **触发前提**：任务达到 COMPLETED **且发生过供应商切换**（`implementation_attempts`
  存在 attempt≥2）。无切换任务扣费价=完成供应商价，天然无差价，零开销跳过。
- **实际价计算**：与扣费同源——`_recalculate_task_power`（最终 `ai_tools.implementation`
  + duration + context 修饰符，DB 热更新价格优先）。
- **实扣金额**：`ai_tools.transaction_id` 关联扣费流水原额（与失败退费同一锚点）。
- **补收 best-effort**：余额不足或 perseids 扣费失败仅记日志（本次让利），不重试
  不追债；流水号幂等保证不会重复补收。
- **灰度开关**：动态配置 `billing.settle_diff_enabled`（默认开，可随时关闭止血）。
- **历史口径**：补偿脚本只退不补（历史少扣不向用户追收，避免争议）。

## 3. 实现

### 3.1 核心（`utils/computing_power.py`）

- `settle_task_success_diff(ai_tool, task_type=None) -> Optional[int]`
  返回正数=退差、负数=补收、None=未结算。幂等（两前缀任一流水存在即跳过）、
  异常整体吞掉（不影响任务成功状态更新）。
- `settle_success_diff_for_task(task_id)`：挂钩统一入口，内部重查 ai_tools
  获取切换后的最终 implementation。

### 3.2 挂钩点（5个成功终态写入处，置 COMPLETED 后调用）

| 文件 | 路径 | 调用方式 |
|---|---|---|
| `task/visual_task.py` | 同步API成功（`_submit_new_task`） | `asyncio.to_thread` |
| `task/visual_task.py` | 异步本地/fallback成功（`_handle_task_success`） | `asyncio.to_thread` |
| `task/download_queue_task.py` | 下载worker成功（正常） | `asyncio.to_thread` |
| `task/download_queue_task.py` | 下载worker成功（max_try兜底） | `asyncio.to_thread` |
| `task/sync_task_executor.py` | 同步执行器成功 | 直接调用（进程池worker） |

⚠️ **新增任务成功终态写入点时必须同样挂钩**（搜索 `settle_success_diff_for_task`）。

### 3.3 常量（`config/constant.py`）

`DIFF_REFUND_TXN_PREFIX = 'diff-refund-'`、`DIFF_CHARGE_TXN_PREFIX = 'diff-charge-'`。

## 4. 前端展示（`web/computing_power_logs.html`）

三页面算力弹窗（iframe 共用该页）新增徽标：

- `diff-refund-` → 蓝色徽标「⇄ 切换补差」（en: ⇄ Switch Refund）
- `diff-charge-` → 蓝色徽标「⇄ 切换补收」（en: ⇄ Switch Charge）
- 与既有「↩ 失败返还」并列；流水摘要剥离类型前缀后显示 前8…后4。
- i18n key：`txn_diff_refund` / `txn_diff_charge`（zh-CN、en）。

## 5. 历史补偿（`script/settle_history_switch_diff.py`）

```bash
# 干跑出清单（默认）
comfyui_env=prod python script/settle_history_switch_diff.py
# 确认后实际发放（受 billing.settle_diff_enabled 开关控制）
comfyui_env=prod python script/settle_history_switch_diff.py --execute
# 可选过滤
comfyui_env=prod python script/settle_history_switch_diff.py --user 1534 --task 28928
```

- 扫描 status=2 且切换过且有扣费流水的任务；实际价按**当前价格表**估算
  （价格热更新过，清单已标注口径）；幂等可重跑。

## 6. 测试

`tests/utils/test_settle_success_diff.py`（13个用例）：多扣退差（55→14 退41）、
少扣补收（16→80 补64，用 site0 代码默认价避免依赖生产热更新价）、未切换跳过、
diff=0 跳过、幂等跳过、实扣缺失跳过、开关关闭跳过、补收失败/HTTP异常不抛、
字段缺失跳过、包装函数三态。前端 jsdom 渲染 11 项断言（三徽标/前缀剥离/样式隔离）。

## 7. 已知取舍

- 补收失败=本次让利（无债务记录），可由补偿脚本口径审计发现；
- 差价按结算时点的当前价格表计算（价格热更新会导致与扣费时点价不一致，
  与失败退费重算口径一致）；
- 任务成功前的多个中间态（DOWNLOADING 等）不结算，仅在 COMPLETED 终态结算一次。
