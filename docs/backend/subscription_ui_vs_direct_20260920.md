# 订阅套餐界面优化：首期加赠并入算力 + 对比直接购买突出差额（2026-09-20）

## 背景

- 首订加赠原先以独立角标「首期订阅加赠 X 算力」展示，与每期算力割裂，首期的价格优势不直观。
- 29.9 入门版等订阅套餐相对「算力充值 Tab 直接购买」的算力优势没有露出，转化引导不足。

## 一、改动内容（web/index.html + web/js/index_app.js + web/css/subscription.css）

### 1. 首订加赠并入首期算力（不再独立角标）

- 套餐卡片首屏算力主数字 = **首期合计**（每期到账 computing_power + 首订加赠 first_period_bonus，
  仅 `first_bonus_eligible=true` 时并入），标注「· 首期」。
- 主数字下方**小字标注「之后每期 X 算力」**（常规到账口径）。
- 支付面板金额行同步：`/月 · 首期到账 X 算力，之后每期 Y 算力`（无资格时为 `/月 · 每期 Y 算力`）。
- 老用户（无首订资格）与升级流程：保持「⚡ X 算力/期」原样，不出现首期标注
  （升级档位本就不重复享首订加赠，见 subscription_plan_upgrade.md）。

### 2. 对比直接购买突出「多多少算力」

- 套餐卡片新增高亮角标「🔥 比直接购买多约 X 算力」（`.sub-plan-save`），与保留的
  「≈ 基础档 X 倍算力」倍数标注（`.sub-plan-mult`，`planMultipleText`）上下排列；
  倍数标注对最低档（入门版）不展示（恒为"基础档"无信息量，返回空串隐藏）。
- 折算口径（数据驱动，`index_app.js`）：
  - 参考单价 = **价格最低的常规算力包**（`price >= 1`，排除 0.1 元首充福利包；
    算力取 `granted_computing_power || computing_power`，与充值 Tab 展示口径一致）；
  - 直接购买等值算力 = `round(套餐价 × 参考单价)`；
  - 差额 = 首屏算力（首期含加赠；升级按每期常规） − 等值算力，**仅当为正时展示角标**，
    参考单价缺失（充值包未加载）时不展示。
- 以现行配置测算（granted=88 邀请口径，9.9 元包参考）：
  入门版首期 528 vs 等值 266 → **多约 262 算力**；老用户每期 328 → 多约 62 算力。
- 「约」字不可省：等值算力为单价比例折算，非整包整数倍。

### 3. 样式与缓存

- `web/css/subscription.css`：新增 `.sub-plan-power-first` / `.sub-plan-power-sub` / `.sub-plan-save`，
  `.sub-plan-power` 加粗放大（首屏算力为主卖点）；`.sub-plan-mult` 保留（最低档隐藏）；
  移除失效的 `.sub-plan-bonus`。
- `index.html` 引用版本戳 `?v=f7165` → `?v=20260920b`（防浏览器缓存旧样式/脚本）。

## 二、测试

- `auto_test/e2e/test_subscription_ui.py` 同步：
  - 新用户：主数字 528 含「首期」+ 小字「之后每期 328 算力」，无 `.sub-plan-bonus`；
  - 老用户：无首期标注；支付面板「首期到账 528 算力，之后每期 328 算力」；
  - 新增 `TestSubscriptionVsDirectSave`：角标文案 262/62、空充值包不展示、
    mock 含 0.1 元首充福利包验证其被排除。

## 三、上线注意

- 纯前端静态文件改动（无后端接口/数据库变更）；让运维**重启服务并强刷（Ctrl+F5）**以加载新 CSS。
- 充值套餐配置（RECHARGE_PACKAGES / COMMISSION_TIERS）调整时，角标数字随前端折算自动变化，
  若出现某档差额 ≤ 0 该档角标自动隐藏（不会展示负向文案）。
