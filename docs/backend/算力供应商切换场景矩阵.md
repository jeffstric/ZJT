## 三、历史漏洞与修复对照

| 漏洞 | 根因 | 修复 |
|---|---|---|
| 失败退费按切换后供应商价格重算（16/80，刷分1.9W） | 退费依赖被切换改写的 `implementation` 重算 | 按扣费流水原额退 + `refund-` 幂等（develop_668） |
| 退费不可对账、可重复 | 退费流水号随机 uuid | `refund-{原流水号}` 派生 + 退前检查（develop_668） |
| 成功不结算差价（贵扣便宜用） | 成功终态无结算 | 双向差价结算 + 五终态挂钩（develop_669） |
| 任务过期不退费 | 过期分支漏调退费 | 过期分支补退费（本次，develop_669） |

**共性教训**：算力结算正确性 = 扣费流水锚定 + 全终态覆盖 + 幂等。
新增失败终态必须调退费、新增成功终态必须调 `settle_success_diff_for_task`（搜索关键词定位全部挂钩点）。
