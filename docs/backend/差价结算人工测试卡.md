# 算力差价结算 — 人工测试卡（供员工执行）

> 前置条件：测试环境已部署 `develop_f623` 分支；使用测试账号（有足够算力余额）。
> 涉及页面：首页（或故事板/工作流页均可）右上角 → 算力日志弹窗。
> 全程约 35 分钟；案例按难度递增，案例1-2 必测，案例3 为核心新功能建议必测。

---

## 案例1：算力日志弹窗 — 识别三种徽标（5分钟，零准备）

**步骤**：
1. 打开首页，点开「算力日志」弹窗；
2. 浏览历史记录，找到有"失败返还"字样的条目；
3. 把鼠标悬停在某条记录下方灰色小标签（单号）上，停留2秒；再点击它一次。

**预期看到**：
- 绿色徽标「↩ **失败返还**」出现在部分 + 分记录的标题位置（这些是任务失败后退回的算力）；
- 普通记录显示「➕ 增加」「➖ 扣除」；
- 每条记录下方有灰色的「单号 xxxxxxxx…xxxx」小标签；
- 悬停显示完整单号；点击后标签短暂变为「✓ 已复制」（剪贴板里是完整单号）。

**通过标准**：三种徽标/文案显示正确，点击复制有反馈。

---

## 案例2：失败返还 — 金额必须原额退回（10分钟）

**步骤**：
1. 记下当前算力余额（记为 **A**）；
2. 提交一个**注定失败**的视频生成任务：提示词写明显违规内容（如涉政/色情描述），时长选最短的档位（扣费最少，记扣费为 **X**）；
3. 等待任务失败（通常1-3分钟，失败原因会显示"内容审核未通过"或"任务失败"）；
4. 打开算力日志，找到这笔记录。

**预期看到**：
- 一条「➖ 扣除」记录，金额 X；
- 紧随其后一条带「↩ 失败返还」徽标的「➕」记录，**金额与 X 完全相等**；
- 当前余额回到 **A**（一分不多一分不少）。

**通过标准**：返还金额 = 扣减金额（不相等立即报告，属于严重BUG）。

## 案例3：切换补差 — 用了便宜供应商，多扣的要退差（20分钟，核心新功能，需管理员配合准备）

**背景**：任务先按贵供应商扣费，失败后自动切换到便宜供应商并成功时，系统应自动退还差价，日志显示「⇄ 切换补差」徽标。

**准备（管理员做一次）**：
- 在测试环境把首选供应商（多米）的 API Key 临时配成无效值，确保备用供应商（慧梦/站点1）配置正常可用；
- ⚠️ 确认测试账号未启用「固定此供应商」（首页 → 用户设置 → 服务商偏好，保持「系统自动选择」或不勾"固定"）——固定后失败不切换，测不到本案例。

**步骤**：
1. 记下余额 A；
2. 提交一个正常内容的视频生成任务（选一个你熟悉价格的时长档位，如 15 秒）；
3. 等待生成完成（首选失败会自动切换，任务最终应成功出片）；
4. 打开算力日志看这笔的记录组合。

**预期看到**（以"按站点1价格扣80、最终慧梦完成（15秒价20）"为例）：
- 一条「➖ 扣除」80；
- 一条蓝色徽标「⇄ **切换补差**」的「➕」记录，金额 **60**（= 80 − 20）；
- 余额变化 = A − 20（等于实际完成供应商的价格，**而不是扣掉的80**）；
- 点单号复制流水号，交给开发可进一步核对。

**测试后（管理员恢复）**：把多米 API Key 恢复原值。

**通过标准**：出现「⇄ 切换补差」徽标；退差金额 = 扣费 − 实际完成供应商的当前价格；余额最终变化等于便宜供应商的价格。

---

## 附：异常反馈口径

测试中发现以下任一情况，**立即截图并记录单号**上报：
- 失败返还金额 ≠ 扣减金额（案例2）；
- 任务成功但没有任何补差记录，且余额按贵价格扣（案例3）；
- 同一任务出现两条返还/补差记录；
- 「⇄ 切换补收」徽标出现且金额异常大（补收理论上仅在"便宜扣费、贵渠道完成"时出现小额）。
