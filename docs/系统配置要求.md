# 系统配置要求

本文档说明运行 ZJT Server 的硬件和软件配置要求。

> **重要说明**：本服务仅作为接口调用的中间层，视频生成、LLM 等计算密集型任务均由外部 API 服务完成。因此服务本身对硬件要求较低。

---

## 部署模式说明

### 单机版（个人使用）
- 适用场景：个人开发、测试、小规模内容创作
- 用户数量：1-3 账号
- 部署方式：本机直接运行

### 多用户版（团队使用）
- 适用场景：团队协作、工作室、商业部署
- 用户数量：10+ 账号
- 部署方式：独立服务器 + 多客户端访问

## 网络要求

### 单机版

- **最低**：稳定宽带连接，下载速度 > 10 Mbps
- **推荐**：宽带连接，上传/下载速度均 > 50 Mbps
- **用途**：调用外部 API（LLM、TTS、视频生成服务）

### 多用户版

- **最低**：服务器上行/下行各 10 Mbps
- **推荐**：服务器上行/下行各 100 Mbps
- **其他**：
  - 建议配置静态 IP 或域名
  - 考虑 CDN 加速（如使用七牛云存储）
  - 配置防火墙规则（仅开放必要端口）

## 部署建议

### 单机版部署

1. **安装 MySQL**：使用项目自带的 `bin/mysql` 目录
2. **配置环境变量**：设置 `PYTHONUTF8=1`（Windows）
3. **双击启动**：运行 `start.bat` 或 `点我启动.exe`
4. **访问地址**：`http://localhost:9003`

### 多用户版部署

1. **选择服务器**：使用云服务器或自建服务器
2. **配置环境**：安装 Python 3.12、MySQL 8.0+
3. **服务管理**：使用 systemd/supervisor 管理服务进程
4. **反向代理**：配置 Nginx 处理 HTTPS、负载均衡
5. **监控告警**：配置日志监控和异常告警（如 Sentry）
6. **备份策略**：定期备份数据库和用户文件

## 故障排查

### 内存不足

- 症状：服务响应慢
- 解决：增加内存、清理缓存

### 磁盘空间不足

- 症状：无法上传文件、生成任务失败
- 解决：清理 `files/` 目录、迁移到更大存储、启用云存储

### 数据库连接池耗尽

- 症状：大量 500 错误、响应超时
- 解决：增加 MySQL `max_connections`、优化查询、增加连接池大小

### 企业安全策略拦截（Device Guard / WDAC）

- 症状：启动 `start.bat` 时输出 `'D:\...\bin\uv\uv.exe' was blocked by your organization's Device Guard policy.`，随后报 `[WARN] Official source failed, retrying with China mirror...` 与 `[ERROR] Failed to download Python automatically` 后退出
- 根因：部署包内自带的二进制（`bin\uv\uv.exe`、`bin\python\...\python.exe`、`bin\mysql`、`bin\ffmpeg` 等）均为**未数字签名**的便携式程序。客户机器的企业安全策略（Windows Defender Application Control，旧称 Device Guard；下称 WDAC）阻止其执行。**这是执行权限被系统拦截，与网络无关**——脚本误判为下载源不可用而切换国内镜像重试，同样失败
- 影响：不仅 Python 无法自动下载；即使手动补齐 `bin\python`，后续 `uv run` 启动服务时同样会被拦截。放行范围必须覆盖整个 `bin` 目录，而不是单个文件
- 排查步骤（在客户机器上执行）：
  1. 事件查看器 → 应用程序和服务日志 → Microsoft → Windows → **CodeIntegrity** → Operational，查找**事件 ID 3077**（已被拦截），详情中含被拦截文件与生效策略 GUID
  2. 管理员 PowerShell 检查智能应用控制（SAC）状态：
     ```powershell
     Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\CI\Policy' -Name VerifiedAndReputablePolicyState
     ```
     值为 `1`（强制）或 `2`（评估）说明 SAC 在工作；为 `0` 则拦截来自企业 WDAC 策略
  3. Windows 11 22H2+ 可用 `Citool.exe --list-policies` 列出当前生效的 WDAC 策略，与事件 3077 中的 GUID 对照
- 解决方案（按拦截机制选择）：
  - **智能应用控制（SAC）**：设置 → 隐私和安全性 → Windows 安全中心 → 应用和浏览器控制 → 智能应用控制设置 → 关闭。注意 SAC 关闭后无法重新开启
  - **企业 WDAC 策略**（需客户 IT 管理员操作，三选一）：
    1. 将该机器移出 WDAC 策略范围（AD 中移出 GPO 链接的 OU，或 Intune 中移出设备组），重启生效。专用服务器推荐此方式
    2. 用微软官方 **WDAC Policy Wizard** 创建补充策略（Supplemental Policy）：为部署目录添加路径规则 `%OSDRIVE%\<部署目录>\bin`（动作 Allow），导出 `.cip` 后部署——Windows 11 执行 `Citool.exe --update-policy <文件>.cip`；Windows 10 将 `.cip` 复制到 `C:\Windows\System32\CodeIntegrity\CIpAllow\Active\` 后重启。路径规则对后续升级替换文件持续有效，推荐此方式
    3. 单机快速验证（哈希规则）：`New-CIPolicy -ScanPath '<部署目录>\bin' -Level Hash -MultiplePolicyFormat -UserPEs -FilePath 'zjt-bin.xml'`，转换为 `.cip` 后按上一条方式部署。注意按哈希匹配，包升级后需重新生成，仅用于验证
  - **AppLocker**（若同时存在，报错一般为 "blocked by group policy"）：`secpol.msc` → 应用程序控制策略 → AppLocker → 可执行规则 → 新建路径规则 `<部署目录>\bin\*`，动作允许，应用于 Everyone
- 转交客户 IT 时建议附带：CodeIntegrity 3077 事件（含策略 GUID）、需放行的完整目录路径、说明该软件包为无安装器的便携式部署、自带未签名二进制

## 附录：并发配置参考

### 关于 max_concurrent_slots 配置

`runninghub.max_concurrent_slots` 参数**不与服务器硬件性能相关**，而是根据您在 RunningHub 购买的套餐来确定。每个套餐有对应的并发任务上限，请根据您的套餐设置此值。

### 单机版并发配置

```yaml
# config.yml
runninghub:
  max_concurrent_slots: 3  # 根据您的 RunningHub 套餐设置

workflow:
  poll_status_interval: 30  # 轮询间隔（秒）
```

### 多用户版并发配置

```yaml
# config.yml
runninghub:
  max_concurrent_slots: 10  # 根据您的 RunningHub 套餐设置

task_queue:
  max_retry_count: 50  # 增加重试次数
  task_expire_days: 14  # 延长任务有效期

workflow:
  poll_status_interval: 15  # 更频繁轮询
```
