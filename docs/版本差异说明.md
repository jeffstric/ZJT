# 社区版 / 商业版差异说明

系统通过 `config_dev.yml` 的 `edition.mode` 与 `enterprise/` 目录共同判定版本
（`config/constant.py` 的 `Edition` 类）：`edition.mode=enterprise` **且**
`enterprise/` 目录存在、并通过 `enterprise/version.json` 版本兼容校验
（`utils/enterprise_loader.py`）后，才视为商业版。

商业版的"放行/增强"代码全部位于 `enterprise/` 目录，通过启动时的
`enterprise.register(app)` 注入开源仓库提供的公共门面（Provider 模式）。
企业模块缺失或加载失败时自动回落社区行为（fail-closed）。

## 差异点一览

| 能力 | 社区版 | 商业版 | 开源门面 / 卡点 | 商业实现 |
|---|---|---|---|---|
| 注册用户数 | 最多 10 人（`COMMUNITY_MAX_REGISTERED_USERS`，config/constant.py） | 不限 | `services/registration_quota.py`（卡点在 `perseids_server/services/auth_service.py` 的 `AuthService.register`） | `enterprise/services/registration_quota_provider.py` |
| RunningHub 密钥池 | 全局单密钥 | 多密钥轮换/熔断 | `task/runninghub_key_pool.py` | `enterprise/services/runninghub_key_pool_provider.py` |
| API 聚合站点数 | 仅 1 个站点 | 多站点 | `config/strategy/edition_strategy.py` | — |
| 邀请佣金 | 无 | 有 | — | `enterprise/routes/commission.py` 等 |

## 注册人数限制实现要点

- 计数使用 `model/users.py` 的 `UsersModel.get_total_count()`，达到上限时注册接口
  返回 `success=False` 及提示文案，前端原样展示。
- 只拦截注册入口，不影响存量用户登录；首个用户（自动成为 admin）不受限。
- 企业模块加载失败时 `utils/enterprise_loader.py` 会 `reset_provider()` 回滚，
  恢复社区限制。
- 测试：`tests/services/test_registration_quota.py`（社区行为）、
  `enterprise/tests/test_registration_quota_provider.py`（商业放行）。
