# 社区版 / 商业版差异说明

版本判定由 `config/constant.py` 的 `Edition.get_mode()` 完成，需同时满足
两个条件才视为商业版：
1. 配置文件 `edition.mode = enterprise`；
2. `enterprise/` 代码目录实际存在。

> 注意：`Edition.get_mode()` **不**校验 `enterprise/version.json` 的版本兼容性——
> 版本兼容校验发生在启动加载阶段（`utils/enterprise_loader.py` 的 `discover()`
> 读取 `enterprise/version.json`，核对 `min_core_version` / `max_core_version`），
> 与运行时的版本模式判定是两个独立环节。校验不通过时 enterprise 模块不会被
> `load()`，Provider 不注入，等效回落社区行为。

配置文件由 `config/config_util.py` 的 `get_config_path()` 按环境变量
`comfyui_env` 选择：未设置时为 `config_dev.yml`（开发默认），设置后为
`config_{env}.yml`（如生产环境 `comfyui_env=prod` → `config_prod.yml`）。
`run_prod.py` 启动时会设置 `comfyui_env=prod`。

商业版的"放行/增强"代码全部位于 `enterprise/` 目录，通过启动时的
`enterprise.register(app)` 注入开源仓库提供的公共门面（Provider 模式）。
企业模块缺失或加载失败时自动回落社区行为（fail-closed）。

商业能力校验在**进程内**完成：仅 Web 的 FastAPI startup 会初始化许可证运行时。
**Scheduler、剧本拆分独立 worker、同步任务进程池**等非 Web 进程不会触发 ASGI
lifespan，启动时须调用 enterprise 提供的后台 bootstrap 入口（见
`scripts/running/run_scheduler.py`、`run_script_split_worker.py`、
`task/sync_task_executor.py`）。未 bootstrap 时商业能力 fail-closed。
详细设计与运维说明仅在 **enterprise 私有文档**中维护，不写入开源主仓。

## 差异点一览

| 能力 | 社区版 | 个人版（Studio） | 企业版（Enterprise） | 开源门面 / 卡点 | 商业实现 |
|---|---|---|---|---|---|
| 注册用户数 | 最多 10 人（`COMMUNITY_MAX_REGISTERED_USERS`，config/constant.py） | 不限 | 不限 | `services/registration_quota.py`（卡点在 `perseids_server/services/auth_service.py` 的 `AuthService.register`） | `enterprise/services/registration_quota_provider.py` |
| RunningHub 密钥池 | 全局单密钥 | 多密钥轮换/熔断 | 多密钥轮换/熔断 | `task/runninghub_key_pool.py` | `enterprise/services/runninghub_key_pool_provider.py` |
| API 聚合站点数 | 仅 1 个站点 | 多站点 | 多站点 | `config/strategy/edition_strategy.py` | — |
| 邀请佣金 | 无 | 有 | 有 | — | `enterprise/routes/commission.py` 等 |
| 对白情感向量 TTS | 无（method=0） | 无（method=0） | 有：拆分产 emo_vec + 自动配音 method=2 | `services/dialogue_emotion.py` | `enterprise/services/dialogue_emotion/`（许可证 `edition=enterprise`） |

## 注册人数限制实现要点

- 计数使用 `model/users.py` 的 `UsersModel.get_total_count()`，由
  `AuthService.register` 取得后传入门面 `check_allowed(total_count)`；
  门面自身不读数据库，便于测试 mock 与跨仓库解耦。达到上限时注册接口
  返回 `success=False` 及提示文案，前端原样展示。
- **并发说明（社区版软上限）**：社区版 `check_allowed` 仅做一次计数快照判断，
  **不**串行化"计数 + 落库"。并发注册时多个请求可能读到相同计数同时放行，
  导致实际人数略超上限。社区版不保证注册人数严格不超过上限（注册仅影响
  计数，不涉及权限/支付，超限无安全风险）。生产环境 gunicorn 多 worker
  （多进程）部署时情况更明显。如需严格上限，请购买商业版（Provider 注入后
  不再计数）。此前曾用进程级 `threading.Lock` 串行化，但因多 worker 下进程间
  不互斥、形同虚设，已移除（避免"已解决并发"的错觉）。
- 只拦截注册入口，不影响存量用户登录；首个用户（自动成为 admin）不受限。
- 企业模块加载失败时 `utils/enterprise_loader.py` 会 `reset_provider()` 回滚，
  恢复社区限制。
- 测试：`tests/services/test_registration_quota.py`（社区行为）、
  `enterprise/tests/test_registration_quota_provider.py`（商业放行）。
