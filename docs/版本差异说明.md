# 社区版 / 商业版差异说明

版本判定由 `config/constant.py` 的 `Edition.get_mode()` 完成，需同时满足
两个条件才视为商业版：
1. 配置文件 `edition.mode = enterprise`；
2. `enterprise/` 代码目录实际存在。

> 注意：`Edition.get_mode()` **不**校验 `enterprise/version.json` 的版本兼容性——
> 版本兼容校验发生在启动加载阶段（`utils/enterprise_loader.py` 的 `discover()`
> 读取 `enterprise/version.json`，核对 `min_core_version` / `max_core_version`），
> 与运行时的版本模式判定是两个独立环节。校验不通过时 enterprise 模块不会被
> `load()`，Provider 不注入，等效回落社区行为。

配置文件由 `config/config_util.py` 的 `get_config_path()` 按环境变量
`comfyui_env` 选择：未设置时为 `config_dev.yml`（开发默认），设置后为
`config_{env}.yml`（如生产环境 `comfyui_env=prod` → `config_prod.yml`）。
`run_prod.py` 启动时会设置 `comfyui_env=prod`。

商业版的"放行/增强"代码全部位于 `enterprise/` 目录，通过启动时的
`enterprise.register(app)` 注入开源仓库提供的公共门面（Provider 模式）。
企业模块缺失或加载失败时自动回落社区行为（fail-closed）。

商业能力校验在**进程内**完成：仅 Web 的 FastAPI startup 会初始化许可证运行时。
**Scheduler、剧本拆分独立 worker、同步任务进程池**等非 Web 进程不会触发 ASGI
lifespan，启动时须调用 enterprise 提供的后台 bootstrap 入口（见
`scripts/running/run_scheduler.py`、`run_script_split_worker.py`、
`task/sync_task_executor.py`）。未 bootstrap 时商业能力 fail-closed。
详细设计与运维说明仅在 **enterprise 私有文档**中维护，不写入开源主仓。

商业版能力（接口模块、品牌定制、RH 密钥池、邀请佣金、供应商自动切换等）还要求
**商业许可证已激活**：未激活（enforce 模式）时对应管理端 API 返回 403，admin
后台按 `features.*` 显示锁定 UI，须先在许可证管理页激活后再使用。

## 激活用户数配额实现要点

- **口径**：激活用户 = `users.status = 1`（正常）；禁用（0）与待审核（2）
  不计入。管理员可经 `PUT /api/admin/users/{id}/status` 禁用用户释放名额，
  再启用/审核通过其他用户（启用转正常时二次校验配额）。管理员不能将自己
  置为禁用（0）或待审核（2）——待审核账号无法登录，将失去重新登录入口。
  计数使用
  `model/users.py` 的 `UsersModel.get_active_count()`，由调用方传入门面
  `check_allowed(active_count)`；门面自身不读数据库。
- **卡点（两处）**：
  1. 注册 `AuthService.register`（`perseids_server/services/auth_service.py`），
     无论 `require_admin_approval` 是否开启都先校验，防止待审核账号无限堆积；
  2. 管理员把用户置为正常（审核通过/重新启用）时
     （`api/admin.py` 的 `PUT /users/{user_id}/status`）。
  达到上限时注册接口返回 `success=False`、管理端返回 400，前端原样展示。
- **商业版分档**：`enterprise/services/license/security_config.py` 的
  `EDITION_DEFAULT_MAX_ACTIVE_USERS`（studio_lite=1 / studio=10 /
  enterprise_lite=20 / enterprise=None 不限）。许可证 JWT
  `limits.max_active_users`（正整数）可覆盖默认值，<=0 视为不限，
  缺失/非法回退默认值——用于早期购买客户人数较多、按许可证上浮的场景
  （由厂商在授权服务器 `limit_json` 中配置）。
- **许可证不可用降级**：商业部署许可证未激活/过期/吊销且无宽限租约时，
  配额回落社区口径（1 人），保证未激活许可证前能注册首个管理员
  （首个注册用户自动成为 admin）。
- **存量兼容**：登录不校验配额，升级后已有激活用户不受影响，仅新增
  注册/激活被新上限拦截。
- **并发说明（软上限）**：`check_allowed` 仅做一次计数快照判断，不串行化
  "计数 + 落库"，并发注册/启用下实际人数可能略超上限（人数计数不涉及
  权限/支付，超限无安全风险）。生产环境 gunicorn 多 worker（多进程）部署
  时情况更明显；此前曾用进程级 `threading.Lock` 串行化，但因多 worker 下
  进程间不互斥、形同虚设，已移除。
- 企业模块加载失败时 `utils/enterprise_loader.py` 会 `reset_provider()` 回滚，
  恢复社区限制。
- **管理端展示**：`GET /api/admin/dashboard` 返回 `active_users` /
  `max_active_users`（null 表示不限）；商业版
  `GET /api/admin/commercial-license/status` 返回 `user_quota`。
  激活用户数**超过**上限时，管理端仪表盘顶部展示警告条，引导购买商业版本
  或禁用用户释放名额（未激活商业版本即社区版 1 人上限，存量超限时触发；
  等于上限为"满员"，新增已被卡点拦截，不告警）。
- 测试：`tests/services/test_registration_quota.py`（社区行为）、
  `enterprise/tests/test_registration_quota_provider.py`（分档/覆盖/降级）、
  `tests/api/test_admin_user_status_quota.py`（管理端启用卡点）、
  `enterprise/tests/license/test_verifier.py`（新 edition 验签）。
