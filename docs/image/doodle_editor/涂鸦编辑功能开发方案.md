# 涂鸦编辑（Doodle Editor）功能开发方案

> 目标：在 `web/video_workflow.html` 工作流中，模仿火山引擎方舟（Ark）控制台 Seedream 体验页的「涂鸦编辑」弹窗，为图片节点提供手绘标注能力。涂鸦后的图片作为 AI 生图/图生视频的参考输入，配合提示词实现"按草图改图"。
>
> 本文档供开发智能体直接使用。第一部分是对火山原版的实测记录（产品互动逻辑），第二部分是本项目的落地方案。
>
> 探索截图存档于 `docs/image/doodle_editor/*.png`，文中以 `[图NN]` 引用。

## 一、火山原版功能实测记录

测试页面：`https://console.volcengine.com/ark/region:cn-beijing/experience/gen_image?model=doubao-seedream-5-0-pro-260628`（Doubao-Seedream-5.0-pro 体验页）。

### 1. 入口与整体流程 [图12, 图10]

```
输入区上传/已有图片缩略图
   └─ 点击缩略图 → 弹出浮层：大图预览 + 底部「涂鸦编辑」按钮
        └─ 点击「涂鸦编辑」→ 打开涂鸦编辑弹窗（全屏遮罩 modal）
             ├─ 点「确认」→ 按钮变 loading + 上传进度百分比 [图11]
             │     → 底图+涂鸦合成一张图上传 → 替换输入区原图 → 关闭弹窗
             └─ 点 X 关闭 → 若有未确认内容，弹「确定退出吗？关闭后，本次涂鸦编辑内容将不会保存。」[图09]
                   → 取消 / 确认退出（丢弃涂鸦）
```

另外示例区（"试试以下示例"）中带「涂鸦编辑」标签的卡片，点击"体验同款"会把示例图+提示词填入输入区，再走上面的入口。

- **底部工具栏**（居中横排，32px 图标按钮，激活态浅蓝底高亮）：

### 3. 各工具交互细节（实测）

- **选择工具**：
  - 点击任意涂鸦元素 → 元素被选中：显示选中框（蓝/紫色描边）+ 8 个白色方形控制点 + 框下方一个圆形旋转手柄 [图06]。
  - 拖动元素内部 = 移动；拖控制点 = 缩放；拖旋转手柄 = 旋转；按 `Delete` 删除选中元素（实测有效）。
  - **底图本身也是可选中对象**：点画布空白或图片 → 整图出现 8 控制点选中框 [图05]，可拖动/缩放底图。
  - 点空白处取消选中。
- **画笔**：点击激活后，工具栏正上方弹出粗细面板（横向滑块 + 右侧 px 数值，默认 `6`）[图02]。在画布上拖拽画自由线条，圆头笔刷，颜色=当前色。再次点击画笔按钮或切换到其他工具，面板收起。
- **橡皮擦**：点击激活同样弹出粗细面板。**注意：自动化实测中点击/拖拽均未产生可见擦除效果**（疑似笔画级删除且命中判定严格，或存在未观察到的机制）。本实现自行定义行为，见方案部分建议。
- **文字 T**：激活后点击画布 → 点击处直接进入输入态键入文字（无独立输入框 UI），颜色跟随当前色；`Enter` 或点击别处完成输入，文字成为可选中的元素 [图04]。
- **矩形**：激活后在画布上拖拽画出**空心矩形**（仅描边，线宽跟随画笔粗细，颜色=当前色）。松开即完成，成为一个元素。
- **颜色**：点击色块按钮，在工具栏上方弹出横向色板，固定 7 色 [图03]：

  | 色 | 实测 RGB | 约 HEX |
  |---|---|---|
  | 红（默认） | 238,63,56 | `#EE3F38` |
  | 黄 | 250,197,21 | `#FAC515` |
  | 绿 | 22,179,100 | `#16B364` |
  | 蓝 | 56,123,255 | `#387BFF` |
  | 黑 | 11,11,15 | `#0B0B0F` |
  | 灰 | 120,120,145 | `#787891` |
  | 白 | 255,255,255 | `#FFFFFF` |

  当前选中色上有 ✓ 标记；选择后色板收起，工具栏色块同步更新。颜色对之后新建的所有元素（画笔/矩形/文字）生效。
- **撤销 / 重做**：按操作步进。一次笔画、一个矩形、一段文字、一次移动/缩放/旋转、一次删除、一次清空各算一步。
- **清空**：弹二次确认框「清空画板内容？清空后可以通过撤销恢复。」取消/确认 [图08]。确认后清空全部涂鸦元素（不清底图），且**可通过撤销恢复**。
- **上传**：打开系统文件选择框，`accept=".jpg,.jpeg,.png,.webp,.bmp,.tiff,.tif,.gif,.heic,.heif,image/*"`，单选。选择后**替换底图**（涂鸦内容保留与否未实测，建议替换时清空涂鸦）。
- **原始比例**：点击弹出比例菜单：原始比例 / 16:9 / 4:3 / 1:1 / 3:4 / 9:16 [图07]。切换画布输出比例（影响合成输出图的尺寸比例）。
- **确认**：按钮变为 loading 态并显示上传进度百分比（如「确认 32%」）[图11]，完成后关闭弹窗，输入区缩略图替换为合成图。

### 4. 产品设计意图

涂鸦（框选、画箭头、画草图轮廓、写字）+ 提示词共同构成对 Seedream 模型的编辑指令，例如实测页面预置提示词："根据手绘草图对图像进行编辑。在左下角标记区域添加一叠真实的杂志或艺术画册，并在右侧标记区域添加一个带杯碟的陶瓷杯咖啡。移除所有草图线条。保持构图不变。"——涂鸦是给模型看的"视觉指令"，不是最终成品图的一部分。

## 二、本项目落地方案

### 1. 总体思路

项目已有**涂色编辑器**（`web/js/image_coloring_editor.js` + `web/css/image_coloring_editor.css`），其"动态注入 modal + `open(url, context, onComplete)` + dataURL 回调"模式已验证可用。涂鸦编辑器**仿照它新建独立文件**（遵守 AGENTS.md 第 3 条：css/js 独立成文件），不复用其像素快照历史——因为涂鸦需要元素选中/移动/删除，必须采用**对象模型 + 重绘**架构。

### 2. 新增 / 修改文件

| 文件 | 动作 | 说明 |
|---|---|---|
| `web/js/image_doodle_editor.js` | 新增 | 涂鸦编辑器全部逻辑，挂全局 `window.imageDoodleEditor = { open, close }` |
| `web/css/image_doodle_editor.css` | 新增 | 弹窗与工具栏样式，z-index 参考涂色编辑器（10050） |
| `web/video_workflow.html` | 修改 | `</body>` 前引入上述两个文件（与 `image_coloring_editor.js` 引入位置相邻，约 :1369 附近） |
| `web/js/image_node.js` | 修改 | 图片节点增加「涂鸦编辑」按钮与处理函数（紧邻现有「涂色编辑」按钮 :169、处理逻辑 :515-578） |
| `web/i18n/locales/zh-CN/video_workflow.json`、`en/video_workflow.json` | 修改 | 新增 `doodle_*` 文案键（参考已有 `coloring_*` 先例） |
| `docs/image/doodle_editor/` | 已有 | 本方案与探索截图 |

### 3. 编辑器架构

```
open(imageUrl, { nodeId, onComplete })
  │
  ├─ ensureModalDom()        // 动态注入 modal DOM（含工具栏、两层 canvas、确认/关闭按钮）
  ├─ fetch(imageUrl) → blob → createImageBitmap   // 必须经 proxyImageUrl() 防跨域污染 canvas
  ├─ 计算 contain 缩放与画布布局
  └─ 进入交互循环（对象模型驱动）
```

**对象模型**（核心，所有涂鸦元素都是对象，canvas 负责重绘）：

```js
// doodleState
{
  tool: 'select' | 'pen' | 'eraser' | 'text' | 'rect',
  color: '#EE3F38',          // 7 色之一
  lineWidth: 6,              // 显示像素，换算见坐标系
  elements: [                // 涂鸦元素数组（绘制顺序即 z 序）
    { id, type: 'stroke', points: [{x,y}...], color, width },        // 画笔一笔
    { id, type: 'rect', x, y, w, h, color, width },                  // 矩形（含旋转角 rotation）
    { id, type: 'text', x, y, text, color, fontSize },               // 文字
  ],
  selectedId: null,
  undoStack: [], redoStack: [],   // 操作栈：{action:'add'|'update'|'delete'|'clear', before, after}
  image: { bitmap, naturalW, naturalH, x, y, w, h, rotation },       // 底图（可选中/拖动/缩放）
  ratio: 'original' | '16:9' | '4:3' | '1:1' | '3:4' | '9:16',
}
```

**坐标系（关键决策）**：元素几何一律存储在**图片自然像素坐标系**（相对原图分辨率），渲染时乘以 `displayScale = 显示尺寸 / 自然尺寸`。好处：确认合成时按原图分辨率导出，输出图不损失清晰度；显示缩放变化（窗口 resize、比例切换）只需重绘。

**渲染**：每帧（或每次变更后）`render()`：清空 → 画底图 → 按序画元素 → 画选中框（8 控制点 + 旋转手柄）。单层 canvas + 对象重绘即可，无需双层。

**撤销/重做**：命令模式。每次"提交型"操作（落笔完成、矩形完成、文字提交、移动/缩放/旋转结束、删除、清空）生成一条 `{action, before, after}` 压入 `undoStack`，同时清空 `redoStack`。undo = 应用 before 并移入 redoStack；redo 反之。栈上限 50 防内存膨胀。

**文字输入**：点击画布后，在该位置绝对定位一个透明背景的 `<textarea>`（DOM 覆盖在 canvas 上），自动聚焦；`Enter`（不含 Shift）或失焦 → 提交为 `text` 元素并移除 textarea；`Escape` 取消。字号按 lineWidth 映射（如 `fontSize = lineWidth * 4`，14~96px 区间）。

**橡皮擦（自行定义，替代原版未确认行为）**：采用**对象级删除**——橡皮模式下按住拖动，路径命中的元素（点到 stroke 折线距离 < 容差、点落在 rect 边框附近、点落在 text 包围盒内）被收集，松开时一次性删除（记一条 undo 记录）。实现简单、行为可预期，且与"元素对象"架构自洽。粗细面板的值作为命中容差。

**选择工具命中检测**：按元素逆序（顶层优先）做命中测试（stroke：点到线段距离 ≤ width/2+4；rect：边线附近或内部；text：包围盒）。选中后：
- 元素内部拖动 = 移动（更新 x,y 或 points 整体偏移）
- 8 控制点拖动 = 缩放（角点等比，边点单向）
- 旋转手柄拖动 = 旋转（`rotation` 字段；stroke 类型可简化为不支持旋转，仅 rect/text 支持）
- `Delete`/`Backspace` = 删除选中元素

**比例切换**：改画布显示框的宽高比，底图在新框内 contain 重排；合成输出时按所选比例裁剪/扩展画布（默认"原始比例"= 底图比例，输出与原图同尺寸）。

**确认合成**：新建离屏 canvas（尺寸 = 输出比例 × 原图分辨率），`drawImage` 底图 + 按序重绘全部元素 → `toBlob('image/png')` → `uploadFile()` → onComplete 回填。**导出必须用原图分辨率**，不要用显示尺寸。

### 4. 节点侧集成（`web/js/image_node.js`）

复用现有涂色编辑的完整链路（:515-578），几乎照抄：

1. 节点按钮区「涂色编辑」旁（:169 附近）加按钮「涂鸦编辑」，门禁沿用 `canEditImageNode`（:9，需已有图片且未在上传中）。
2. 点击处理：
   ```js
   imageDoodleEditor.open(proxyImageUrl(node.data.url), {
     nodeId: node.id,
     onComplete: async ({ blob }) => {
       const file = new File([blob], `doodle_${Date.now()}.png`, { type: 'image/png' });
       const res = await uploadFile(file);            // api.js:3 → POST /api/video-workflow/upload
       node.data.url = res.data.url;                  // 回填服务器 URL
       node.data.preview = '';                        // 让预览走 url
       updateImageNodePreview(node);                  // 刷新节点预览（沿用现有函数名）
       safeAutoSave();                                // node_base.js:473
     }
   });
   ```
3. **序列化兼容**：节点 data 只存服务器 URL（`workflow.js:567-587` 会剥离 blob:/data:），工作流重新加载后图片正常复原（AGENTS.md 第 4 条天然满足）。涂鸦编辑过程态**不持久化**（与火山一致：退出即丢弃）。
4. 注意 `uploadFile` 是异步的，符合 AGENTS.md 第 1 条非阻塞要求；按钮在请求期间置 loading 态防重复提交。

### 5. 冲突与注意事项（务必检查）

- **全局快捷键冲突**：`web/js/events.js:430-440` 绑定了工作流级 `Ctrl+Z` 撤销、:445 `Delete` 删除节点。涂鸦弹窗打开期间，弹窗内的 `keydown` 必须 `stopPropagation()`，并把 Ctrl+Z / Ctrl+Shift+Z / Delete 路由到编辑器自己的撤销/重做/删除元素，否则会误删工作流节点。弹窗关闭时移除监听。
- **canvas 跨域污染**：底图必须经 `proxyImageUrl()`（state.js:142）获取后再 drawImage，否则 `toBlob` 抛 SecurityError。参考 `image_coloring_editor.js:356-365` 的 fetch→blobURL 写法。
- **Esc 键**：文字输入态 Esc = 取消输入；普通态 Esc 不直接关弹窗（避免误触丢失），关闭一律走 X + 二次确认。
- **关闭确认**：`elements.length > 0` 时走 `showConfirmModal`（state.js:216-267，Promise 化）提示"关闭后，本次涂鸦编辑内容将不会保存"；无内容直接关。
- **清空确认**：同样走 `showConfirmModal`："清空画板内容？清空后可以通过撤销恢复。"
- **触屏**：参考涂色编辑器 :124-248 同时绑 mouse + touch 事件（passive:false + preventDefault 防页面滚动）。
- **非阻塞**：所有 web 交互不引入同步 XHR；上传走现有 `uploadFile`（fetch）。

### 6. UI 规格（模仿火山）

- 弹窗：居中 modal，白色圆角卡片（约 90vw × 85vh，最大 1200px），遮罩 `rgba(0,0,0,.45)`。
- 标题「涂鸦编辑」左上，X 右上。
- 画布区：浅灰（`#f5f6f7`）容器，图片阴影轻投影。
- 工具栏：底部居中横排 32×32 图标按钮，激活态浅蓝底（`#e8f0ff`）+ 主色图标；分组用 1px 竖分隔线。
- 主色：火山为蓝紫 `#5B5BD6` 系；本项目沿用现有主题主色即可，不必强抄。
- 粗细面板/色板：工具栏正上方浮出的小白卡片（圆角 + 阴影），切换工具或点击别处收起。
- 确认按钮：右下，主色填充，loading 时禁用 + 显示"确认中…"（原版显示上传百分比，本项目 uploadFile 无进度回调，可简化为 spinner + 禁用）。
- 图标：内联 SVG（stroke=currentColor），可从现有 `video_workflow.css`/nodes.js 图标风格延续；不引第三方图标库。

### 7. 开发步骤（建议顺序，每步可独立验证）

1. **骨架**：新建 js/css，注入 modal，加载底图 contain 显示，关闭/X/退出确认可用。在 html 引入。
2. **画笔 + 颜色 + 粗细**：对象模型、render 循环、笔画绘制、色板、粗细面板。
3. **撤销/重做/清空**：命令栈 + 两个确认弹窗。
4. **矩形 + 文字**：拖拽矩形；DOM textarea 文字输入与提交。
5. **选择/移动/缩放/删除**：命中检测、控制框、Delete；底图选中移动可选做（火山支持，建议做移动，缩放可裁剪到二期）。
6. **橡皮擦（对象级删除）**、**上传替换底图**、**比例菜单**。
7. **确认合成 + 节点集成**：image_node.js 按钮 + 上传回填 + safeAutoSave；验证工作流保存/刷新后图片复原。
8. **i18n + 文档**：补 zh-CN/en 文案；同步更新本文档状态。

### 8. 验收标准

- 图片节点出现「涂鸦编辑」按钮，有图时可点，弹窗正常打开并显示当前图片。
- 画笔/矩形/文字/颜色/粗细均可用；撤销重做清空行为符合预期；清空单二次确认且可撤销恢复。
- 选中元素可移动/缩放/删除；弹窗内 Delete、Ctrl+Z **不触发**工作流节点删除/撤销。
- 确认后节点图片更新为合成图（原图分辨率），`safeAutoSave` 触发；保存并刷新页面后节点图片仍为涂鸦后的图。
- 退出未确认时有挽留弹窗；确认退出后内容丢弃。
- 上传替换底图、比例切换（至少"原始比例" + 1:1 + 16:9）工作正常。

### 2. 与原方案的差异（实现时的取舍）

- **旋转手柄未实现**：验收标准仅要求移动/缩放/删除，选中框为 8 控制点（无旋转手柄）。`stroke`/`text` 缩放为对角锚点等比缩放，`rect` 支持 8 向独立缩放；底图支持选中移动与等比缩放。旋转可二期补充（元素模型已预留无 rotation 字段）。
- **确认按钮无上传百分比**：按方案 6 节建议简化为「确认中…」禁用态（`uploadFile` 无进度回调）。
- **二次确认弹窗为编辑器内置实现**（z-index 10100）：宿主 `showConfirmModal`（state.js）z-index 为 10000，会被涂鸦弹窗（10050）遮挡，故内置了一份同风格确认框。
- **键盘防线双保险**：弹窗打开时 `initSession` 会 focus 到 modal 卡片（`tabindex="-1"`），键盘事件经 modal keydown 拦截 `stopPropagation`；同时 events.js 全局处理器检查 `imageDoodleEditor.isOpen()` 让位。实测弹窗内 Delete/Ctrl+Z 不会误删工作流节点。
- **合成导出面积保护**：输出画布超过 64M 像素时等比降采样，防浏览器 canvas 上限。
