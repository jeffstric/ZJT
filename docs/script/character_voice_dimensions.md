# 角色五维声音（对白身份指纹）

## 背景

角色卡的 `behavior` 以前只写"说话方式：语气特点、口头禅"，导致下游写对白时角色区分度主要靠口头禅，盖住名字后认不出谁在说话。

本次在 `character-creator` skill 中引入**五维声音框架**：先看角色怎么看待世界、怎么处理关系，再用词汇和节奏微调。目标效果是**只看对话内容，就能清楚知道是哪个角色**。

## 五个维度

| 维度 | 问的问题 | 可选倾向 |
|------|----------|----------|
| ① 注意什么 | 开口时第一反应盯住什么 | 流程型 / 感受型 / 风险型 / 体面型 |
| ② 怎样证明 | 想说服别人时习惯用什么方式 | 举证型 / 规则型 / 经验型 / 关系型 / 逼表态型 |
| ③ 控制距离 | 称呼、人称、公开/私下如何控制亲疏 | 直呼名字 vs 职位称谓；"我们" vs "你们/他们"；私下/公开两套说法；避免代词 |
| ④ 怎样隐藏 | 真实意图不想直说时的遮掩方式 | 多解释 / 反问 / 开玩笑 / 沉默 / 改话题 / 过度精确（选 0-2 个） |
| ⑤ 压力下如何变形 | 紧张、愤怒、心虚时说话往哪个方向变 | 变短变冷 / 变粗暴或更正式 / 重复同一句 / 突然坦白 / 退回方言口头禅或沉默 |

**核心判断标准（换人测试）**：把同一句话或同一场景换给不同角色说，台词是否还能成立。换了人仍然完全成立，说明这个声音还没立住。

**选取原则**：每个主要角色选 2-3 个稳定倾向；①②区分度最高、主角必选，③④⑤挑最突出的 1-2 个；倾向必须能从性格、职业、背景推导，禁止凭空贴标签。

## 落库格式

无表结构变更。五维声音写入角色 JSON 的 `behavior` 字段（自由文本，`create_character_json` 无 schema 限制）：

```
说话方式：[语气特点、口头禅]
声音维度：注意什么[倾向+具体表现]；怎样证明[倾向+具体表现]；控制距离[称呼/人称/公开私下习惯]；怎样隐藏[倾向，无则整段省略]；压力变形[压力下说话的变化方向]
换人测试：同一句「你怎么看这个方案？」TA 会说「[只有这个角色才会说的原话]」
肢体语言：…
日常习惯：…
情绪表达：…
```

「声音维度」和「换人测试」是主角、重要配角的必填项，临时角色可省略。

## 下游消费

story-writer 通过 `read_character_json` 读取角色卡参考说话方式（原有链路不变），`behavior` 中的声音维度随角色卡一起被读取，无需代码改动。

## 手工验收要点

1. 用一部多人剧本走 character-creator 流程，确认提问环节出现声音维度选项（含例句），用户不回答时智能体会自行给出候选倾向。
2. 检查生成的角色 JSON：主要角色的 `behavior` 含「声音维度」与「换人测试」两行；任意两个主要角色的「注意什么+怎样证明」组合不重复。
3. 让 story-writer 写一场至少 3 个角色的对话，盖住角色名自测能否分辨谁在说话。
